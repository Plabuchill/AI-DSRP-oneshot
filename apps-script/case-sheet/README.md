# case-sheet — บันทึกเคสจาก Case Intake ลง Google Sheet + เก็บไฟล์ต้นฉบับใน Google Drive (FEAT-INTAKE-06)

Apps Script web app ที่ผูกกับ Google Sheet หนึ่งไฟล์ หน้า Case Intake เรียกเมื่อเจ้าหน้าที่กด **ยืนยัน** เคส
(เขียนทับแถวเดิมถ้า Case ID ซ้ำ — เช่นแก้แถวที่ยืนยันแล้วแล้วยืนยันใหม่) และดึงทุกแถวมาแสดงเป็นตาราง
"ข้อมูลที่บันทึกใน Google Sheet" บนหน้าเว็บ

ไฟล์ต้นฉบับ (PDF/JPEG/PNG ที่อัปโหลด) ถูกเก็บในโฟลเดอร์ **`AI-DSRP ไฟล์ต้นฉบับ Case Intake`** ใน Drive ของเจ้าของสคริปต์
(สร้างให้เองครั้งแรก) ชื่อไฟล์ขึ้นต้นด้วย Case ID และลิงก์ไฟล์อยู่ในคอลัมน์ "ลิงก์ไฟล์ต้นฉบับ (Drive)" — อัปโหลดครั้งเดียวต่อ Case ID
(ยืนยันซ้ำไม่สร้างไฟล์ซ้ำ) ไฟล์เป็นส่วนตัวของเจ้าของ ถ้าเจ้าหน้าที่คนอื่นต้องเปิดลิงก์ได้ ให้แชร์โฟลเดอร์นี้ให้เขา

- รับเฉพาะคำขอที่แนบ Firebase ID token ของผู้ที่ล็อกอินเว็บ ai-dsrp (ตรวจกับ Firebase ทุกครั้ง)
- ไม่ต้องสร้าง API key/Service Account และไม่มีค่าใช้จ่าย (อยู่ในโควตาฟรีของ Apps Script)
- ⚠️ PDPA: ชีตมีชื่อ เลขประจำตัวประชาชน และที่อยู่ผู้ป่วย — แชร์ชีตเฉพาะเจ้าหน้าที่ที่จำเป็น

## ติดตั้ง (ทำครั้งเดียว ~5 นาที)

1. สร้าง Google Sheet ใหม่ (ตั้งชื่ออะไรก็ได้ เช่น `AI-DSRP Case Intake`)
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. ลบโค้ดเดิมในไฟล์ `Code.gs` แล้ววางเนื้อหาจาก [`Code.gs`](./Code.gs) ในโฟลเดอร์นี้ → กด 💾 บันทึก
4. ปุ่ม **Deploy → New deployment** → ไอคอนเฟือง เลือก **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - กด **Deploy** → Google จะขอสิทธิ์ (Authorize access) ให้เลือกบัญชีตัวเองแล้วกดอนุญาต
     (ถ้าขึ้น "Google hasn't verified this app" ให้กด Advanced → Go to ... (unsafe) — เป็นสคริปต์ของคุณเอง)
5. คัดลอก **Web app URL** (ลงท้าย `/exec`) ไปใส่ใน [`prototypes/v1/sheet-config.js`](../../prototypes/v1/sheet-config.js) ที่ `CASE_SHEET_URL`
   และ (ไม่บังคับ) ใส่ลิงก์ของตัวชีตที่ `CASE_SHEET_VIEW_URL` เพื่อให้มีปุ่ม "เปิด Google Sheet"
6. `firebase deploy --only hosting`

ทดสอบว่า deploy แล้ว: เปิด Web app URL ในเบราว์เซอร์ ต้องเห็น `{"ok":true,"service":"AI-DSRP case sheet",...}`

## แก้สคริปต์ภายหลัง (รวมถึงอัปเดตเพื่อเปิดการเก็บไฟล์ลง Drive)

1. วาง `Code.gs` ฉบับใหม่ทับของเดิมใน Apps Script → 💾 บันทึก
2. ถ้าสคริปต์ใหม่ใช้สิทธิ์เพิ่ม (เช่น Drive) ให้เลือกฟังก์ชัน `getFolder_` ในแถบเครื่องมือด้านบนแล้วกด **Run** หนึ่งครั้ง →
   Google จะขอสิทธิ์ใหม่ → อนุญาต (โฟลเดอร์ใน Drive จะถูกสร้างตอนนี้)
3. **Deploy → Manage deployments → ✏️ (Edit) → Version: New version → Deploy**

URL เดิมใช้ต่อได้ — ถ้ากด New deployment แทนจะได้ URL ใหม่ ต้องแก้ `sheet-config.js` ตาม

## คอลัมน์ในชีต (แท็บ `ทะเบียนผู้ป่วย`)

58 คอลัมน์ตามแบบทะเบียนผู้ป่วยของหน่วยงาน (ลำดับ · เดือน · สัปดาห์ที่ · ชื่อ-สกุล · เลขบัตร ปชช. · … · การควบคุมโรค)
ตามด้วยคอลัมน์ของระบบ: Case ID · ทีมรับผิดชอบ · ผู้บันทึก · บันทึกเมื่อ · ลิงก์ไฟล์ต้นฉบับ (Drive)

ระบบเขียนเฉพาะคอลัมน์ที่มีข้อมูลจาก Case Intake:

| คอลัมน์ | ค่าที่ระบบใส่ | เขียนเมื่อ |
|---|---|---|
| ลำดับ | เลขลำดับถัดไป (มากสุดในคอลัมน์ + 1) | เพิ่มแถวครั้งแรกเท่านั้น |
| เดือน / สัปดาห์ที่ | จากวันที่เริ่มป่วย — ชื่อเดือนไทย, สัปดาห์ระบาดวิทยา (เริ่มวันอาทิตย์ แบบ MMWR) | ทุกครั้งที่ยืนยัน |
| ชื่อ-สกุล, เลขบัตร ปชช., ที่อยู่, ตำบล (ที่อยู่), วันที่เริ่มป่วย, รหัสโรค, DX. | จาก OCR Review | ทุกครั้งที่ยืนยัน |
| พิกัด ละติจูด ลองติจูด (ที่อยู่) | "lat, lng" | ทุกครั้งที่ยืนยัน |
| วันที่รับแจ้ง | วันที่กดยืนยันในระบบ (วว/ดด/ปปปป พ.ศ.) | เพิ่มแถวครั้งแรกเท่านั้น |
| คอลัมน์ระบบ 5 คอลัมน์ท้าย | Case ID, ทีม, อีเมลผู้บันทึก, เวลา, ลิงก์ Drive | ทุกครั้งที่ยืนยัน (ลิงก์ Drive ครั้งแรกเท่านั้น) |

คอลัมน์อื่นทั้งหมด (เบอร์โทร เพศ อายุ อาชีพ ที่ทำงาน สถานที่รักษา Lab ข้อมูลควบคุมโรค HI/CI น้ำมัน ฯลฯ) **เจ้าหน้าที่กรอกในชีตเอง**
และระบบไม่เขียนทับเมื่อยืนยันเคสซ้ำ — ค่าว่างจากระบบก็ไม่ลบค่าที่มีอยู่ในชีต

สคริปต์หาคอลัมน์จาก**ชื่อหัวคอลัมน์** (ไม่สนช่องว่าง/ขึ้นบรรทัดใหม่) ไม่ใช่ตำแหน่ง — ย้าย แทรก หรือเพิ่มคอลัมน์ของตัวเองได้
แต่**อย่าเปลี่ยนชื่อหัวคอลัมน์**ที่ระบบเขียน (ถ้าเปลี่ยน ระบบจะเพิ่มคอลัมน์ชื่อเดิมต่อท้ายใหม่) และอย่าลบคอลัมน์ Case ID

Case ID ขึ้นต้น `CI-` = เคสจากเอกสารที่อัปโหลดจริง (มีไฟล์ใน Drive), `DEMO-` = เคสตัวอย่างที่ฝังในหน้าเว็บ (ไม่มีไฟล์จริง)
แท็บ `Cases` จากสคริปต์รุ่นก่อนไม่ถูกแก้หรือลบ — ลบเองได้ถ้าไม่ใช้แล้ว
