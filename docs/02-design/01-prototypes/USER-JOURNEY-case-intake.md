## Persona

**หลัก — วรรณา ศรีสมบูรณ์** เจ้าหน้าที่ รพ.สต. ประจำอำเภอเมือง มีหน้าที่นำส่งรายงานผู้ป่วยที่ต้องเฝ้าระวังโรค (เอกสาร PDF/JPEG/PNG จากแผนกผู้ป่วยนอก — รง.506 ที่กรอกด้วยลายมือเป็นส่วนใหญ่) เข้าระบบทุกครั้งที่มีเคสใหม่ ก่อนส่งต่อให้ทีมสอบสวนโรคดำเนินการ — touchpoint หลักคือการอัปโหลดไฟล์ แล้ว**เทียบ/แก้/กรอกข้อมูลในตารางจากภาพต้นฉบับเอง** เพราะ OCR ฟรีอ่านลายมือไม่ได้ ก่อนเลือกโรคและกดยืนยัน

**รอง — ทีมสอบสวนโรค เขต 3** ผู้รับแจ้งเตือนปลายทางเมื่อวรรณายืนยันเคสสำเร็จ ไม่ได้เป็นผู้ลงมือใน journey นี้โดยตรง แต่เป็นผู้เห็นผลลัพธ์ที่ระบบส่งต่อให้ (ดูขั้นตอน 9a)

## Trigger

วรรณาได้รับเอกสารรายงานผู้ป่วยที่ต้องเฝ้าระวังโรค (สแกน/ถ่ายรูปจากแผนกผู้ป่วยนอก) และต้องนำเข้าระบบให้ทีมสอบสวนโรคทราบเร็วที่สุด เพื่อไม่ให้การสอบสวน/ควบคุมโรคล่าช้า

## Pain point ที่ journey นี้แก้ (และที่ยังแก้ไม่ได้ในรุ่นนี้)

- ✅ แก้บางส่วน: เดิมเจ้าหน้าที่ต้องพิมพ์ข้อมูลจากเอกสาร PDF/JPEG/PNG ด้วยมือทีละฟิลด์ทั้งหมด — ตอนนี้ OCR จริงในเบราว์เซอร์ (Tesseract.js ฟรี ไฟล์ไม่ออกนอกเครื่อง) ดึงชื่อ/เลขบัตร/ที่อยู่/วันที่เริ่มป่วย/พิกัด (ถ้ามี) ให้อัตโนมัติ **เมื่อเอกสารเป็นข้อความพิมพ์ที่ชัดเจน** พร้อมแผงภาพต้นฉบับให้เทียบ ระบบเดาโรคให้จากข้อความ เตือนเลขบัตรที่ checksum ไม่ผ่าน และทิ้งค่าที่อ่านเป็นขยะเป็นค่าว่างแทนการเดาใส่ ก่อนเจ้าหน้าที่ตรวจสอบ/แก้ไข/ยืนยันเอง (human-in-the-loop เต็มรูปแบบ) — ลดเวลาป้อนข้อมูลและลดโอกาสพิมพ์ผิดสำหรับเอกสารพิมพ์ แต่สำหรับ รง.506 ลายมือยังต้องกรอกเองจากภาพ (ดูข้อ "ยังไม่แก้" ด้านล่าง)
- ⚠️ ยังไม่แก้ (backlog):
  - **OCR อ่านลายมือไทย/ช่องติ๊กโรคใน รง.506 ไม่ได้** (ทดสอบแล้ว) — ถ้าอ่านได้ <2 ช่องหลัก ระบบแจ้ง "ระบบอ่านข้อมูลจากเอกสารนี้ได้น้อยมาก…" และเปิดโหมดแก้ไขให้กรอกเองจากภาพ ซึ่งเอกสารจริงส่วนใหญ่ยังต้องพิมพ์ด้วยมืออยู่ดี การอ่านลายมือด้วย Claude Vision (Cloud Function `extractCaseReport`) เป็น backlog รอ deploy Cloud Function/อัปเกรด Firebase Blaze (`FEAT-INTAKE-05` ส่วนที่เป็น AI Vision — ยังไม่เชื่อมจริง)
  - ปุ่ม "ให้ AI ช่วยตรวจสอบ" (`FEAT-INTAKE-10`) ต้องมี Cloud Function บน Firebase Blaze ซึ่งยังไม่ได้ deploy จึงใช้ไม่ได้ในสภาพแวดล้อมปัจจุบัน และ AI ช่วยจัดประเภทโรค (`FEAT-INTAKE-11`) ไม่มีปุ่มบน UI แล้ว เหลือเพียง dropdown เลือกเอง + ระบบเดาด้วย keyword
  - ค่าผลตรวจ/ผลแล็บไม่ได้อยู่ในตาราง OCR Review แล้ว (ไม่มีคอลัมน์ผลแล็บ) — ข้อมูลโรคระบุผ่าน dropdown รหัส รง.506 อย่างเดียว
  - ไฟล์ต้นฉบับยังไม่ถูกเก็บคู่กับแถวข้อมูลลง Google Sheet/Drive อัตโนมัติ — ลิงก์ "ไฟล์ต้นฉบับ" ในตารางยังเป็น placeholder ที่คลิกไม่ได้จริง (`FEAT-INTAKE-06`, ROADMAP.md Phase 1)
  - พิกัดยังต้องกรอก/ปรับด้วยมือสำหรับเคสจาก OCR เกือบทุกราย (ฟอร์ม รง.506 ส่วนใหญ่ไม่มีช่องพิกัด) เพราะยังไม่มี Geocoding API แปลงที่อยู่เป็นพิกัดอัตโนมัติ (`FEAT-INTAKE-07`, Phase 1)
  - การแจ้งเตือนทีมสอบสวนโรคยังเป็น in-app log ในหน้าเว็บเท่านั้น ยังไม่ส่งผ่าน LINE OA จริงถึงตัวเจ้าหน้าที่ (`FEAT-INTAKE-08`, Phase 1)
  - เคสที่ยืนยันแล้วแก้ไขไม่ได้เลยในรุ่นนี้ — ถ้าพบข้อผิดพลาดหลังยืนยัน ต้องประสานงานนอกระบบ ยังไม่มี unlock flow (`FEAT-INTAKE-09`, Phase 1)
  - ผลลัพธ์ OCR, ภาพต้นฉบับ และผลจาก AI Consistency Check (เมื่อใช้งานได้) เป็น in-memory เท่านั้น หายไปถ้า reload หน้าก่อนกดยืนยัน เพราะ Case Intake ยังไม่มี Firestore document backing สำหรับตัวเคสเองในรุ่นนี้ (ต่างจาก รง.506 ที่ persist จริงแล้ว)

## Traceability กับ Test Spec

โมดูล Case Intake **ยังไม่มี Test Spec** ใน [[../../03-testing/01-test-plan/v1/ACCEPTANCE-CRITERIA|ACCEPTANCE-CRITERIA.md]]/`TEST-PLAN.md` เลย (เอกสารชุดปัจจุบันมีแค่ FR-DASH-01 ถึง 06 สำหรับ Outbreak Dashboard) — จึงไม่มีขั้นตอนใดใน journey นี้ที่ map กับ FR- ที่มีอยู่ได้ **ควรเรียก `qa-doc-builder` ต่อ** เพื่อเขียน Test Plan/Acceptance Criteria ของ `FEAT-INTAKE` โดยเฉพาะ — เมื่อมีแล้ว ขั้นตอน 1-2c/3/4/6/7/8 ควรตรงกับ Test Spec แบบ 1:1 ได้ง่าย (เป็น UI ที่ implement ครบแล้วไม่ใช่ mock) ส่วนขั้นตอน 9a/9b เป็นจุดที่ควรระบุไว้ชัดเจนว่า **อยู่นอกขอบเขตการทดสอบ** จนกว่า `FEAT-INTAKE-08`/`09` จะถูกพัฒนาจริง และขั้นตอน 5/5a/5b (AI ช่วยตรวจสอบ) ก็อยู่นอกขอบเขตเช่นกันจนกว่าจะ deploy Cloud Function `assistCaseReview`
