# User Journey — แปลงเอกสารรายงานผู้ป่วยเป็นข้อมูลพร้อมแจ้งเตือนผ่าน Case Intake

อ้างอิงจาก [[../../01-requirements/01-spec/FEATURE-LIST|FEATURE-LIST.md]] หมวด `FEAT-INTAKE` และสอดคล้องกับ Sequence Flow ที่มีอยู่แล้วใน [[../02-technical/DETAILED-DESIGN|DETAILED-DESIGN.md]] Flow 1 (OCR Review & Confirm Flow), Flow 2 (Manual Geo Adjustment) และ Flow 3 (Notification & Spot Map Query) — โมดูลนี้**ยังไม่มี Test Spec** ใน [[../../03-testing/01-test-plan/v1/ACCEPTANCE-CRITERIA|ACCEPTANCE-CRITERIA.md]] (มีแค่ FR-DASH-01 ถึง 06 สำหรับ Outbreak Dashboard) ดูหัวข้อ Traceability ท้ายเอกสาร

> **สถานะโค้ดจริง ณ วันที่เขียน (2026-09-22)**: OCR extraction (`extractCaseReport`), AI Consistency Check (`assistCaseReview`) และ AI ช่วยจัดประเภทโรคติดต่อ (`suggestDiseaseType`) เชื่อมต่อ Cloud Function จริงแล้วทั้ง 3 ปุ่ม (ไม่ใช่ mock) — ผลลัพธ์ของ AI ทั้งสองปุ่มหลังยังเป็น in-memory เท่านั้น ไม่ persist ลง Firestore เพราะ Case Intake ยังไม่มี Firestore document backing สำหรับตัวเคสเองในรุ่นนี้ ส่วน Google Sheet/Drive, Geocoding API จริง, LINE OA แจ้งเตือนจริง และการ unlock แก้ไขเคสที่ยืนยันแล้ว ยังเป็น backlog ทั้งหมด (ดูตารางขั้นตอนและ Pain point ด้านล่าง)

## Persona

**หลัก — วรรณา ศรีสมบูรณ์** เจ้าหน้าที่ รพ.สต. ประจำอำเภอเมือง มีหน้าที่นำส่งรายงานผู้ป่วยที่ต้องเฝ้าระวังโรค (เอกสาร PDF/JPEG จากแผนกผู้ป่วยนอก) เข้าระบบทุกครั้งที่มีเคสใหม่ ก่อนส่งต่อให้ทีมสอบสวนโรคดำเนินการ

**รอง — ทีมสอบสวนโรค เขต 3** ผู้รับแจ้งเตือนปลายทางเมื่อวรรณายืนยันเคสสำเร็จ ไม่ได้เป็นผู้ลงมือใน journey นี้โดยตรง แต่เป็นผู้เห็นผลลัพธ์ที่ระบบส่งต่อให้ (ดูขั้นตอน 9a)

## Trigger

วรรณาได้รับเอกสารรายงานผู้ป่วยที่ต้องเฝ้าระวังโรค (สแกน/ถ่ายรูปจากแผนกผู้ป่วยนอก) และต้องนำเข้าระบบให้ทีมสอบสวนโรคทราบเร็วที่สุด เพื่อไม่ให้การสอบสวน/ควบคุมโรคล่าช้า

## Pain point ที่ journey นี้แก้ (และที่ยังแก้ไม่ได้ในรุ่นนี้)

- ✅ แก้แล้ว: เดิมเจ้าหน้าที่ต้องพิมพ์ข้อมูลจากเอกสาร PDF/JPEG ด้วยมือทีละฟิลด์ทั้งหมด — ตอนนี้ OCR จริง (Claude Vision ผ่าน `extractCaseReport`) ดึงให้อัตโนมัติ พร้อม AI ช่วยตรวจสอบความสมเหตุสมผล (`assistCaseReview`) และ AI ช่วยจัดประเภทโรคติดต่อ (`suggestDiseaseType`) ก่อนเจ้าหน้าที่ตรวจสอบ/แก้ไข/ยืนยันเอง (human-in-the-loop เต็มรูปแบบ) — ลดเวลาป้อนข้อมูลและลดโอกาสพิมพ์ผิด
- ⚠️ ยังไม่แก้ (backlog):
  - ไฟล์ต้นฉบับยังไม่ถูกเก็บคู่กับแถวข้อมูลลง Google Sheet/Drive อัตโนมัติ — ลิงก์ "ไฟล์ต้นฉบับ" ในตารางยังเป็น placeholder ที่คลิกไม่ได้จริง (`FEAT-INTAKE-06`, ROADMAP.md Phase 1)
  - พิกัดยังต้องปรับด้วยมือเสมอสำหรับเคสจาก OCR จริง เพราะยังไม่มี Geocoding API แปลงที่อยู่เป็นพิกัดอัตโนมัติ (`FEAT-INTAKE-07`, Phase 1)
  - การแจ้งเตือนทีมสอบสวนโรคยังเป็น in-app log ในหน้าเว็บเท่านั้น ยังไม่ส่งผ่าน LINE OA จริงถึงตัวเจ้าหน้าที่ (`FEAT-INTAKE-08`, Phase 1)
  - เคสที่ยืนยันแล้วแก้ไขไม่ได้เลยในรุ่นนี้ — ถ้าพบข้อผิดพลาดหลังยืนยัน ต้องประสานงานนอกระบบ ยังไม่มี unlock flow (`FEAT-INTAKE-09`, Phase 1)
  - ผลลัพธ์จาก AI Consistency Check และ AI ช่วยจัดประเภทโรคติดต่อ เป็น in-memory เท่านั้น หายไปถ้า reload หน้าก่อนกดยืนยัน เพราะ Case Intake ยังไม่มี Firestore document backing สำหรับตัวเคสเองในรุ่นนี้ (ต่างจาก รง.506 ที่ persist จริงแล้ว)

## Traceability กับ Test Spec

โมดูล Case Intake **ยังไม่มี Test Spec** ใน [[../../03-testing/01-test-plan/v1/ACCEPTANCE-CRITERIA|ACCEPTANCE-CRITERIA.md]]/`TEST-PLAN.md` เลย (เอกสารชุดปัจจุบันมีแค่ FR-DASH-01 ถึง 06 สำหรับ Outbreak Dashboard) — จึงไม่มีขั้นตอนใดใน journey นี้ที่ map กับ FR- ที่มีอยู่ได้ **ควรเรียก `qa-doc-builder` ต่อ** เพื่อเขียน Test Plan/Acceptance Criteria ของ `FEAT-INTAKE` โดยเฉพาะ — เมื่อมีแล้ว ขั้นตอน 1-2b/7/8 ควรตรงกับ Test Spec แบบ 1:1 ได้ง่าย (เป็น UI ที่ implement ครบแล้วไม่ใช่ mock) ส่วนขั้นตอน 9a/9b เป็นจุดที่ควรระบุไว้ชัดเจนว่า **อยู่นอกขอบเขตการทดสอบ** จนกว่า `FEAT-INTAKE-08`/`09` จะถูกพัฒนาจริง
