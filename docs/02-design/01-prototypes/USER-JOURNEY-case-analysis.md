# User Journey — วิเคราะห์กลุ่มเคส ร่างรายงานสอบสวนโรค และบริหาร รง.506 ผ่าน Case Analysis

อ้างอิงจาก [[../../01-requirements/01-spec/FEATURE-LIST|FEATURE-LIST.md]] หมวด `FEAT-ANALYSIS` และสอดคล้องกับ Sequence Flow ที่มีอยู่แล้วใน [[../02-technical/DETAILED-DESIGN|DETAILED-DESIGN.md]] Flow 5 (Case Clustering Confirm & Report Flow), Flow 6 (AI Cluster Suggestion Generation) และ Flow 7 (ASM Coordination Chat) — **เฉพาะสาย A** ของ journey นี้ (ดูด้านล่าง) ส่วนสาย B (รง.506) **ยังไม่มี Sequence Flow ใน DETAILED-DESIGN.md เลย** แม้ `FEAT-ANALYSIS-07`/`08`/`09` จะ implement จริงแล้วก็ตาม (ดูหมายเหตุ FEATURE-LIST.md อัปเดต 2026-09-06) — โมดูลนี้**ยังไม่มี Test Spec** ใน [[../../03-testing/01-test-plan/v1/ACCEPTANCE-CRITERIA|ACCEPTANCE-CRITERIA.md]] เลย (มีแค่ FR-DASH-01 ถึง 06 สำหรับ Outbreak Dashboard) ดูหัวข้อ Traceability ท้ายเอกสาร

> **สถานะโค้ดจริง ณ วันที่เขียน (2026-09-22)**: Case Cluster Map/ร่างรายงานสอบสวนโรค (สาย A) และประสานงาน อสม. เป็น **mock ล้วน** ฝังอยู่ใน `case-analysis.js` (ข้อมูล cluster ถูก pre-group ไว้ในโค้ด ไม่ใช่ clustering algorithm จริง, ร่างรายงานประกอบจาก template คงที่ ไม่ใช่ AI generation อิสระ, chatbot เป็น scripted demo ทีละคู่ข้อความ) — ส่วนสาย B (รง.506 ทั้ง flow: สร้าง/AI ช่วยเลือกโรค/พิจารณา/AI สรุปแนวโน้ม) เชื่อม **Firestore + Cloud Function จริง** ผ่าน `case-analysis-506.js`/`new-506-request.js`/`506-request-detail.js` — ต่างจากสาย A ที่เป็น mock ทั้งหมด **ต้องมีอินเทอร์เน็ต** สถานะจริงของ รง.506 คือ **"รอพิจารณา" → "ยืนยัน"/"ไม่ยืนยัน"** (ไม่ใช่ "รออนุมัติ"/"อนุมัติ" — ศัพท์เก่าที่เลิกใช้แล้ว)

## Persona

**หลัก — อนุชา ปิ่นทอง** เจ้าหน้าที่ทีมสอบสวนโรค เขต 3 (นักระบาดวิทยา) มีหน้าที่ตรวจสอบกลุ่มเคสที่ AI เสนอ ร่างรายงานสอบสวนโรคเบื้องต้นให้ผู้บริหาร และบันทึกรายงาน รง.506 (รายงานผู้ป่วยเฝ้าระวังโรค) เข้าระบบเมื่อพบเหตุการณ์ที่ต้องเฝ้าระวัง — ทำงาน 2 sub-journey คนละบริบทในหน้า/กลุ่มหน้าเดียวกัน (`case-analysis.html` และ `new-506-request.html`)

**รอง — ดร.สุนีย์ ศรีสมบัติ** ผู้บริหารเขตสุขภาพ (role category `manager` ตาม `current-user.js`/`ACL.md`) มีสิทธิ์พิจารณายืนยัน/ไม่ยืนยัน รง.506 ที่ทีมสอบสวนโรคบันทึกไว้ และเป็นบทบาทเดียวที่เห็นปุ่ม "ให้ AI ช่วยสรุปแนวโน้มโรค" ในหน้ารายละเอียด รง.506 (`506-request-detail.html`) ก่อนตัดสินใจ

## Trigger

มี 2 trigger แยกกันในโมดูลนี้ เขียนเป็น 2 สาย (sub-journey) ในไฟล์เดียว:

- **สาย A**: อนุชาเห็นว่ามี cluster ใหม่ที่ AI เสนอในหน้า Case Analysis ต้องตรวจสอบและตัดสินใจว่าจะยืนยันหรือไม่ + อาจร่างรายงานส่งผู้บริหารต่อ
- **สาย B**: อนุชาพบเหตุการณ์ที่ต้องเฝ้าระวังและต้องการบันทึกรายงาน รง.506 ใหม่เข้าระบบ ให้ ดร.สุนีย์ พิจารณาต่อ

## Pain point ที่ journey นี้แก้ (และที่ยังแก้ไม่ได้ในรุ่นนี้)

- ✅ แก้แล้ว (สาย A): เดิมทีมสอบสวนโรคต้องรวบรวมเคสที่เกี่ยวข้องกันด้วยมือ/ความจำ — ตอนนี้เห็นกลุ่มที่ AI เสนอไว้ล่วงหน้าพร้อมค่าความมั่นใจ และมีร่างรายงานสอบสวนโรคเบื้องต้นให้แก้ไขต่อแทนการเริ่มพิมพ์จากศูนย์
- ✅ แก้แล้ว (สาย B): เดิมการบันทึก/พิจารณา รง.506 เป็นเอกสารกระดาษหรือไฟล์แยกที่ต้องส่งต่อด้วยมือ — ตอนนี้เป็นฟอร์มดิจิทัลที่บันทึกลง Firestore จริงทันที มี AI ช่วยเลือกประเภทโรคติดต่อ และผู้บริหารเห็น AI สรุปแนวโน้มโรคย้อนหลัง 7 วันประกอบการตัดสินใจ

## Traceability กับ Test Spec
